## Orders are real

> "ORDERS ARE REAL. They are written to a private server-side store, given a
> season-unique code, and visible to staff on any device. NO CARD IS CHARGED."

- Store: **Vercel Blob**, `vsamachta-orders-private` (`store_nYZrW8h8XjIZxFA0`), private access
- Payment stays a preview until the operator connects their own Stripe account
- Confirmation emails are written to a log, not sent, until sending is switched on

This is why a rebuilt-from-scratch backend is dangerous: orders live in that
blob store under a specific path and JSON shape. A reimplementation that guesses
either one makes existing orders invisible to staff.

## Backend map

All persistence is one file deep — swapping to Postgres later means rewriting
`lib/server/kv.ts` alone.

| File | Responsibility |
|---|---|
| `lib/server/kv.ts` | `readJson` / `createJson` / `casJson` / `updateJson` / `listPaths` over the private blob store |
| `lib/server/repo.ts` | orders, per-site index, reserve stock, audit + notification logs |
| `lib/server/pricing.ts` | server-side pricing and cart validation, deadline + grace window |
| `lib/server/auth.ts` | staff session cookie, checkout tickets (HMAC) |
| `lib/server/stripe.ts` | PaymentIntents + webhook verification over `fetch`, no SDK |
| `lib/server/notify.ts` | confirmation text, Resend seam, logging |
| `lib/server/http.ts` | JSON replies, staff guard, rate limit, input cleaning |
| `lib/staff-store.tsx` | what the staff screens read; serialises actions per order |

Content and config live in `lib/data.ts` (levels, `SITES`), `lib/he.ts` (Hebrew
copy, `HE_SITE`), `lib/images.ts` (photo manifest), `lib/trust.ts` (Rav names
and inspection clip — the band stays hidden while it is empty).

Routes: `/api/status`, `/api/checkout/start`, `/api/orders`, `/api/orders/[code]`,
`/api/staff/{login,orders,orders/[code],totals,reserve,demo}`, `/api/webhooks/stripe`.

### Rules worth knowing

- The browser sends **quantities only**. Prices are computed on the server, every time.
- Order codes: 7 characters from `ABCDEFGHJKMNPQRSTUVWXYZ23456789`, claimed by an
  atomic write, so two orders can never share one.
- The deadline is enforced on the server. A cart that reached the payment step
  before it may finish up to `GRACE_MINUTES` (15) afterwards, proved by a signed
  ticket carrying the server's clock.
- Staff screens sit behind `STAFF_PIN`. **If that variable is ever unset the
  screens open up** — and say so on the page.

## Environment variables (Vercel project settings, never in git)

**Set:** `BLOB_READ_WRITE_TOKEN`, `STAFF_PIN`, `AUTH_SECRET`, `GRACE_MINUTES` (15).

**Deliberately unset:** `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` (the
operator's own keys — setting them turns payments on, webhook to
`/api/webhooks/stripe`); `RESEND_API_KEY`, `NOTIFY_FROM`, `NOTIFY_ENABLED`
(nothing sends until `NOTIFY_ENABLED=1`).

Because these are project-level, a git-based production deploy inherits them
unchanged. Nothing needs re-entering to move off CLI deploys.

## Gotchas the build paid for

- **Weak ETags.** Blob `get` returns `W/"abc"` once a blob is big enough to be
  compressed, while `put`/`head` return `"abc"`, and `ifMatch` refuses the weak
  form. Every compare-and-swap failed and the staff listing answered 500.
  Normalised in `kv.ts`; a gate check keeps an index over 1 KB and asserts the
  listing still loads.
- **Stale responses clobbering newer ones.** Parallel staff actions on one order
  each return a whole order; the slowest won, so a set marked handed over
  un-marked itself. Actions are chained per order and only the last outstanding
  response may replace the screen.
- `flex-1` on a button inside a stacked (column) group collapses it to text
  height on phones.
- A Suspense fallback of `null` around a client page lets the footer jump (CLS);
  reserve height.
- Tailwind `transition` animates `outline-color`; read focus colours after ~200 ms.
- Vercel's edge answers Node fetch bursts with 403 challenges; every QA script retries.

- **The esrog is never a render.** Every esrog, lulav and person is a real
  photograph; provenance in `public/img/LICENSES.md`, manifest in `lib/images.ts`.
  Generated images were tried and rejected (lemons, stems on the wrong end, a cup
